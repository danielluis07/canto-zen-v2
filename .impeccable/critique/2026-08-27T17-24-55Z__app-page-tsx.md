## Design Specificity Verdict

Authored for this product, and it holds up at the code layer.

Genuinely authored and not liftable into another brand: the room band's `flexGrow: environment.types.length` (components/home/environments.tsx:41) encoding category count as panel width; two distinct catalog readings with the reason stated in code and honoured in markup (components/home/products-spread.tsx:81-90); hero scrims in the page's own warm white, lightening rather than darkening the photograph (components/home/abertura.tsx:28-38).

Category-default: the section rhythm (header, 4 items, exit link, x4) is conventional editorial-commerce structure — defensible, but not authorship. The footer is a standard four-column link wall.

Deterministic scan: detect.mjs exit 2, 6 `design-system-font-size` advisories. Four are false positives (DESIGN.md documents the 0.8125rem dense-metadata step and the 1.5rem Title upper bound in prose, not frontmatter). Two are real drift: 0.75rem at components/home/products-spread.tsx:61, 1.375rem at components/layout/wordmark.tsx:12.

Browser overlay: injection succeeded, 28 anti-patterns reported. Most are the detector meeting an intentional system (18 `undersized-ui-text` = documented 10px caption step; `kicker-above-heading` x4 and `hero-eyebrow-chip` = documented Section Header eyebrow; `image-hover-transform` x8 = documented product-lift motion). Objective and standing: `low-contrast` x3, `clipped-overflow-container` on the hero, `tight-leading` on the width-ruler plate.

Convergence: detector, Assessment A's in-page measurement, and the parent's own calculation independently produced stone-on-greige = 4.43:1 and oak-deep-on-ground = 4.44:1.

## Overall Impression

Well above portfolio-average with a genuinely considered system (the reduced-motion block switching timeline animations off by name is a detail most production sites get wrong). With imagery set aside, the page's one structural problem is that four middle sections carry identical header weight, identical 112px rhythm and exactly four items each — so a fast scanner reads sections three and five as "that row again." The page presents; it never escalates.

Biggest opportunity: give the page a crescendo. The machinery to differentiate the sections already exists (`lib/catalog-filters.ts` facets, the straddled label, the greige band) and is currently unused on the home surface.

## What's Working

1. The room band encodes a catalog fact in its geometry — panels abut and share hairlines, seams re-route between grid and flex row, flex-grow is the category count. Makes restraint legible as judgment.
2. Two forms for two jobs, with the reason stated in code and honoured in markup.
3. Small screens refuse the easy collapse — filmstrip keeps its 4:5 crop at 74vw with scroll-px-6 snapport alignment; the mobile sheet restates the desktop band's fact.

## Priority Issues

### [P1] The page offers the same catalog five times, and its four middle sections carry identical weight

Five links to /produtos under four labels, two word-for-word identical (app/page.tsx:26, app/page.tsx:36). lib/catalog-filters.ts already defines `entrega=pronta-entrega`, so the "Pronta entrega" exit should land on the filtered catalog, not the bare index.

Why it matters: on a Persuade surface with one goal, repeating the offer five times without escalation gives no reason to act on any particular one. It also drives both cognitive-load failures.

Fix: cut to two exits (hero primary + one section-level exit at peak intent), point each remaining exit at its own filtered view, differentiate sections by form rather than giving every one a full SectionHeader.

Suggested command: /impeccable layout

### [P1] Contrast falls below AA on hover, and in the collection band

--oak-deep on the page ground is 4.44:1 and is the hover colour for every nav link, product name, TextLink and footer link — contrast decreases on interaction. Stone on greige is 4.43:1 (collection band description and eyebrow). Cart badge is the same pair at 10px.

Why it matters: an axe run finds the interactive state is the failing state; failures cluster exactly where tokens leave the warm-white ground they were tuned against.

Fix: darken --oak-deep (app/globals.css:75) from oklch(0.571 0.081 56.6) to ~oklch(0.545 0.081 56.6). Lift the greige band's description to ink. Give the hero catalogue plate the bg-background/85 treatment the width ruler already uses.

Suggested command: /impeccable audit

### [P2] The Sala anchor is the one piece with no measurements, in the section that argues measurements first

getAnchorsByEnvironment (lib/catalog.ts:47) takes the first product per room blindly; for `sala` that is sofa-heron-linho-cru, whose family carries measurements { width: 0, depth: 0, height: 0 } (data/families.ts:7). Degradation is correct — no zeros, no ruler — but the first plate in the most important room cannot state its scale, under a note arguing scale. Its own prose asserts "a largura de 220 cm" while the data denies it.

Fix: prefer the first anchor whose family declares a width, falling back to current behaviour. The graceful-degradation path stays in the code for when it is genuinely needed.

Suggested command: /impeccable harden

### [P2] Nothing de-risks a R$ 9.800 purchase above the footer, and the CNPJ reads as an unfilled template

FSC certification, 5-year structural warranty and free-shipping threshold live only in the footer beneath 18 links. components/layout/footer.tsx:90 prints CNPJ 00.000.000/0001-00 — PRODUCT.md names CNPJ on the never-fabricate list, and an all-zeros one reads as a placeholder nobody filled in. lib/navigation.ts:52 points social links at platform homepages.

Fix: surface the three commitments once in the page body as a hairline-ruled row (already one constant in lib/commitments.ts). Delete the CNPJ rather than zeroing it — an absent registration asserts nothing, which is what the rule wants.

Suggested command: /impeccable harden

### [P2] The hero is the one image container with no placeholder ground, and the availability tag carries no information

components/home/abertura.tsx:16 has no `bg-secondary` where every other image container has one — a failed hero paint leaves the entire first viewport an empty warm-white void with the catalogue plate floating in it. Separately, 8 of 8 items on this page resolve to sage-deep, so the sage/stone availability distinction DESIGN.md asserts is never demonstrated on the surface a reviewer sees. Both are structural, not content-dependent.

Fix: add the greige ground to the hero container. For availability, either mix the anchor set so the stone branch renders, or accept that the tag is decorative here and cut it from the row where all four values are identical.

Suggested command: /impeccable harden

## Cognitive Load — Moderate (2 of 8 failed)

Passing: single focus, chunking, grouping, one-thing-at-a-time, working memory, progressive disclosure.

Failing: visual hierarchy (four sections at identical weight, nothing ranks them); minimal choices (footer's 22 links at terminal position; five undifferentiated routes into the catalog). Page total: 50 links.

## Persona Red Flags

Skeptical recruiter, 30-second scan: the authorship that would win them over — `flexGrow: environment.types.length` — is invisible unless they open environments.tsx:41. The rendered page gives them four evenly-weighted sections and no crescendo, then a footer with a zeroed CNPJ and social links pointing at platform homepages.

Brazilian household comparing on measurements, finish, delivery: Sala — their most likely room — is the one plate with no dimensions. The width ruler DESIGN.md calls the signature fires exactly twice on the whole page and is `hidden lg:flex`, so on a phone it never appears at all. Delivery says 6 semanas on the plates and 3 a 10 semanas in the hero; free shipping, returns and warranty require finding the footer's fourth column.

Mobile shopper, 390px: ~8,600px of scroll with no in-page jump. "Pronta entrega" appears six times within one phone screen (eyebrow, title, note, one sage tag per card) where all four tags say the same thing, because the section filters for exactly that — four labels carrying zero discriminative information, in a system whose stated principle is that nothing is decorative unless it also carries information.

Screen-reader visitor: genuinely well done — skip link, lang="pt-BR", aria-current on the active room, sr-only "largura por profundidade por altura" before the cotas, and all first 15 focusable elements showing a real focus ring at the documented sage-deep colour. The one defect is that --oak-deep at 4.44:1 means contrast drops below AA on hover across every link on the site.

## Minor Observations

- data/enviroments.ts carries an unused on-register `description` per room; the file and its import are also misspelled `enviroments` (PRODUCT.md notes reviewers read the code).
- `.rise` is on every content block except the ProductsRow grid (components/home/products-row.tsx:39) — the one block that does not rise.
- Collection is the only section with no SectionHeader, and has an image link plus a LinkButton to the same href.
- components/layout/nav-links.tsx:11 uses text-xs (12px) where every other micro-label in the system is 11px.
- app/globals.css:46 sets --background: oklch(0.99 0.003 84.6) while DESIGN.md declares warm-white as oklch(0.983 0.006 84.6); --primary-foreground uses the DESIGN.md value, so the one solid control is labelled in a white the page ground never uses.
- On the spread's sm:grid-cols-2, "SOB ENCOMENDA · 6 SEMANAS" wraps to two lines, breaking the single-baseline ledger.
- Two real font-size drifts flagged by the detector: 0.75rem (products-spread.tsx:61) and 1.375rem (wordmark.tsx:12) match no documented step.
- Console hydration error is a LanguageTool browser extension injecting data-lt-installed — not an app defect.
- Assessment B's `resize_window` never changed the viewport, so no true 390px overflow measurement was taken; the mobile pass used a same-origin iframe, which exercises real media queries but is not a true small-viewport render.

## Questions to Consider

1. The room band spends the page's best structural idea encoding category count. Would lead time or price range in that same geometry tell a buyer something they actually weigh?
2. DESIGN.md names the width ruler as the signature. It fires twice on the home page and never on a phone. What should the home page's signature be?
3. What would this page look like if only one section were allowed a SectionHeader and the other three had to earn attention by form alone?
4. In a category where someone commits R$ 9.800 to a piece they cannot sit on, is a home page that mentions returns and warranty nowhere above the footer persuading, or merely presenting?
